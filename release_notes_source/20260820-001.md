# SimpleRisk 20260820-001 Release Notes

## Security Issues
- Updated the single sign-on library to a release that addresses a published security advisory.

## New Functionality
- SimpleRisk now checks that an Extra is compatible with your installed release before installing it, and tells you plainly when the application needs to be upgraded first instead of leaving the install to fail. Extra and release information is now retrieved from `updates.simplerisk.com`; instances with restricted outbound access should make sure that host is reachable.

## Bug Fix
- Fixed the Document Program tables running off the right edge of the screen, which left the Actions column — and with it the edit and delete controls for every document — unreachable without scrolling to the bottom of the page and back.
- Fixed custom fields being lost when creating or editing a framework or control on Define Control Frameworks. Custom field values now also prefill correctly when you open an existing framework or control for editing.
- Fixed the Preferences page reporting that your settings had been saved when nothing had changed, including a duplicated confirmation message for each asset valuation level. The page now saves only what you actually edited and reports accordingly. Also fixed a case where changing the default language at the same time as another preference discarded that other preference.
- Fixed missing single sign-on interface files — stylesheet, scripts, icons, and webfont — in the packaged release.
- Fixed a case where a failed Extra download could remove an already-working copy of that Extra.
- The built-in starter risk and threat catalogs are no longer created during an upgrade. These catalogs are now populated by the Secure Controls Framework import, which provides a more complete and better-maintained set. Existing catalog entries are left untouched, so this affects only instances upgrading from a version that had not yet received them.

## Language Updates
- Refreshed translations across the supported languages.
