# SimpleRisk 20260709-001 Release Notes

## Security Issues
- SR-104: Strengthened protection against forged cross-site actions across the application.
- SR-114: Replaced the external database-backup command with a safer, self-contained backup process.
- SR-119: Required authenticated POST requests for state-changing actions so they cannot be triggered by a simple link.
- SR-120: Hardened output encoding of chart configuration values.
- SR-121: Hardened encoding of redirect destinations.
- SR-383: Hardened output encoding of playbook content.
- SR-751: Tightened permission enforcement on tag-lookup requests.
- SR-856: Hardened output encoding of the governance framework description.
- SR-1651: The management API key is now stored as a secure hash rather than as recoverable text.
- SR-1694: Enforced view-permission checks on compliance file downloads.
- SR-1695: Tightened permission enforcement on marking projects incomplete.
- SR-1696: Tightened permission enforcement on high-privilege fields in the risk-update API.
- SR-1697: Tightened permission enforcement on custom risk-score updates.
- SR-1707: Hardened encoding of administrator-configured colors used in reports and dashboards.
- SR-1718: Required an authenticated POST request for the risk reopen action.
- SR-1720: Restricted the Workflows HTTP Request action to an administrator-managed allow-list of approved destinations.
- SR-1721: Enforced per-module permission checks on internal data-table requests.
- SR-1760: Enforced team-separation checks on single-asset API lookups.
- SR-1767: Required the management API key to be sent as a request header rather than in the URL or form body.
- SR-1775: Enforced module permission checks on risk-report data-table requests.
- SR-1779: Scoped the user-manager API lookup behind a permission check.
- SR-1781: Tightened permission enforcement on risk tooltip requests.
- SR-1782: Tightened permission enforcement on risk review submissions.
- SR-1783: Validated the configured database-backup command path to prevent unsafe execution.
- SR-1784: Enforced permission checks across the remaining risk-management reporting requests.
- SR-1785: Restricted contributing-risks data-table requests to administrators.
- SR-1786: Tightened permission enforcement on review-date corrections.
- SR-1787: Tightened permission enforcement on incident-management configuration changes.
- SR-1788: Tightened permission enforcement on vulnerability-management updates.
- SR-1789: Enforced permission checks on incident-management report views.
- SR-1790: Enforced asset-access checks on the asset verify, discard, and delete actions.
- SR-1791: Scoped questionnaire answer pre-population to the same respondent to prevent cross-respondent disclosure.
- SR-1793: Hardened output encoding of the Jira link shown in the risk detail view.
- SR-1794: Tightened permission enforcement on assessment tag enumeration.
- SR-1798: Hardened output encoding in the risk filtering form action.
- SR-1799: Hardened output encoding of control names in the asset mapped-controls view.
- SR-1800: Hardened output encoding of chart axis titles and restricted chart selection options to an approved allow-list.
- SR-1837: Tightened permission enforcement on questionnaire result approval actions.
- SR-1869: Hardened spreadsheet exports of the Dynamic Risk Report against untrusted content that could be interpreted as a spreadsheet formula.
- SR-1870: Enforced a column-name allow-list and hardened encoding for custom display-settings columns.
- SR-1885: Restricted AI provider connections to an administrator-managed allow-list of approved destinations.
- SR-1897: Hardened workflow-driven updates to rich-text fields against stored malicious content.
- SR-1898: Hardened rich-text fields on controls, exceptions, tests, risks, mitigations, and reviews against stored malicious content.
- SR-1912: Required authenticated POST requests for the Upgrade Extra backup and upgrade actions.

## New Functionality
- (PR #1906): Custom language files can now override only the strings you want and fall back to a base language for everything else, so they no longer need to carry the full string list on every upgrade.

## Performance / Availability
- SR-1680: Faster activation of the Custom Authentication Extra on new installs.
- SR-1682: Faster activation of the Import-Export Extra on new installs.
- SR-1683: Faster activation of the Encrypted Database Extra on new installs.
- SR-1685: Faster activation of the Artificial Intelligence Extra on new installs.
- SR-1850: Faster activation of the Vulnerability Management Extra on new installs.
- SR-1851: Faster activation of the Team-Based Separation Extra on new installs.

## Aesthetics / User-Interface
- SR-1816: The Risk Assessment scheduling frequency now shows a clear disabled indicator instead of an ambiguous "0 days".
- SR-1829: Added confirmation feedback when clicking Save Draft on a questionnaire that has no unsaved changes.

## SimpleRisk Extra Development
- SR-1815: Added a Reopen action for rejected questionnaire results in the Risk Assessment Extra.
- SR-1817: The Risk Assessment Extra now allows editing scheduling and notification fields after a questionnaire has been sent.
- (PR #1802): Added a Risk Assessment Extra API endpoint that returns a respondent's submitted questionnaire answers as structured JSON.
- (PR #1870): Fixed SAML SSO asset and module URLs not resolving correctly with the authentication Extra.
